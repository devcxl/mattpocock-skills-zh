## 它的作用

`prototype` 写**用来回答一个问题的、用完即扔的代码**：这个状态模型感觉对不对、这个界面应该长什么样。问题排在前面，决定之后一切的形状；一个回答错了问题的原型，无论看起来多漂亮，都是纯粹的浪费。

"用完即扔"是写在代码*方式*上的约束，而不是一个会销毁它的承诺。没有测试、没有超出让它跑起来之外的错误处理、没有抽象、没有持久化，因为这些里面没有一样能帮你学到你想学的那一件事。能活下来的是答案，折叠进真正的代码里，以及原型本身，停在一个不出现在 main 上的分支上，作为"答案从这里来"的证据。

## 何时使用

键入 `/prototype`，或者当任务合适时 [agent](https://www.aihero.dev/ai-coding-dictionary/agent) 会自动使用它。

在撞上一个光靠说话敲不定的问题的那一刻使用它：一个边角情况你脑子里装不下的状态机、一个你不看到三个并排版本就想象不出来的界面。[盘问（grilling）](https://www.aihero.dev/ai-coding-dictionary/grilling) 会话恰恰会在这些问题上膨胀：agent 改个说法、你猜一下、范围被不确定性填满。停下盘问，搭出用完即扔的版本，看一眼，然后一句话回答。如果反过来是某样已经构建的东西在作怪、你想知道为什么，用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)；原型探索的是要构建什么，而不是已构建的东西为什么坏了。

你也会不挑自来。[wayfinder](https://aihero.dev/skills-wayfinder) 在它的地图上放 `prototype` 决策 [tickets](https://www.aihero.dev/ai-coding-dictionary/ticket)，干一张就是这个技能。

## 两条分支

问题决定分支，分支产出截然不同的工件：

- **"这个逻辑 / 状态模型感觉对吗？"**：一个**单一可分享的 HTML 文件**。一个自包含的页面，没有构建、没有服务器，任何人双击就能打开。它带一个每次点击后重新渲染的、贴了标签的状态面板、若干让你以任意顺序戳模型的自由按钮，以及带标签的**引导式走查**（一个 tab 一个场景，每个 tab 下放着顺序的按钮）。一切都用领域语言贴标签，所以你可以把它交给设计师、PM 或领域专家，让他们自己感受模型。页面背后的逻辑是一个小的纯模块（reducer、machine、或一组函数），保持不带 DOM 的清洁，让验证过的版本能直接搬进真正的代码。
- **"这个应该长什么样？"**：同一个路由上若干**截然不同的** UI 变体，可通过一个悬浮底栏和 `?variant=` URL 参数切换。变体必须就结构分歧，而不是颜色；三张微调的卡片网格是壁纸，不是原型。它们尽可能渲染在一个真实页面里、对着真实数据和真实密度，因为一个在真空中被评判的变体永远看起来不错。

两者都在内存里保持状态、一开始不需要任何思考、并在每一步之后向你展示完整状态。一旦你发现自己正在硬化其中之一（加一条测试、接上真实数据库、为一个你以后可能想要的场景做泛化），你就停下了原型工作。

## 原型是一手来源

一个完成的原型留下两样东西，它们去到不同的地方。

**答案**（结论加上它敲定的问题）被持久地捕获：一条 commit message、一份 ADR、实现 issue 上的注释。这是 main 分支保留的、折叠进真正代码里的东西。

**原型**是答案来自哪里的可运行证据，它不被删除。它也不属于 main：那里没什么要维护的东西，而且它腐烂得很快。所以它被提交到一个不在 main 上的、用完即扔的 `prototype/<name>` 分支，永远不合并，并留一个 [context pointer](https://www.aihero.dev/ai-coding-dictionary/context-pointer) 指向那条分支，落在实现 issue 上。Main 保持干净；探索保持可被下一个接手工作的人找到并重跑。

## 常见问题

**等等，原型不应该是被删掉的吗？**

不再是了。以前是：搭起来，留住答案，扔掉代码。最尖锐的反对从来不是关于速度的；而是*谁在下一 [session](https://www.aihero.dev/ai-coding-dictionary/session) 里接手工作，他们手上有什么？* 一份原型的散文式摘要丢失了让它有说服力的那点东西。所以现在原型被当作 [primary source](https://www.aihero.dev/ai-coding-dictionary/primary-source)：它落在一个不在 main 上的 `prototype/<name>` 分支，实现 issue 指向它。改变的是代码住在哪里，而不是纪律；它仍然从不合并进 main。

**它以前搭一个终端 app。那个去哪了？**

逻辑分支现在产出一个单一可分享的 HTML 文件。一个终端 app 只能被一个 clone 了仓库、装了运行时的家伙驱动，这恰恰把原型最需要其意见的人排除在外：设计师、PM、知道状态模型本意应该是什么的领域专家。一个双击就能打开、能被邮件发出去的单一自包含文件，能被任何人驱动。底下的纯逻辑模块没变，并且仍然是那份搬进真正代码的部分。

**一个 agent 在我本该实现的时候叫我 `/prototype`。**

已知，这是一个命名问题。`prototype` 是一个通用的、好听的词，对一个不知道流程的 agent 读起来像是"在 tickets 存在之后的显然下一步"，所以即便设计已在对话里完全敲定，它也会被按名字推荐出来。如果你已经知道要构建什么，下一步是 `/implement`，按 ticket 来。仅当一个具体的设计问题真的没敲定、而且光靠说话敲不定时，才去原型化。

**我应该在构建任何生产功能之前原型化整个应用（比如给潜在客户演示）吗？**

那是披着这份技能名字的另一件工件。这里的原型被限定于一个问题，而"整个应用长什么样？"不是一个。整个应用的原型没有自然的停止点，于是它借势变成了生产 app：清理那一遍永远不发生，按原型规则（没有测试、没有错误处理）写下的代码最终出现在用户面前。如果你需要一次销售 demo，把它刻意搭成一次 demo，并明确表示它没有一处是生产的。如果你需要敲定一个设计问题，把它裁到那个问题。

**我怎样在自己的会话里跑它？**

原型住在它自己的目录里，并产生一堆你不想留在问这个问题的那条线程里的 [context](https://www.aihero.dev/ai-coding-dictionary/context)，所以把它跑到别处，只把答案带回来。[handoff](https://aihero.dev/skills-handoff) 是两个方向的桥梁。

**这不是烧 token 的最快方式吗？**

可以是，如果你原型化的问题本来光靠说话就能答，或者让一份原型蔓延到整个功能。重要的对比不是 token 对零；是 [tokens](https://www.aihero.dev/ai-coding-dictionary/token) 对"搭错状态模型、在它有了生产调用者之后才发现"。把问题收窄、把跑动保持简短，开销就成比例。

## 怎样算成功

- 你能用一句话说出原型存在是为了回答什么问题，而且这句话写在 demo 的顶部，不只是在你脑子里。
- 不读代码的人也能驱动逻辑 demo。他们打开文件、按走查 tab 上的按钮、用自己的话描述他们看到的。
- 有人说"等等，那不应该可能"，或者"嗯，我以为是 X"。这是*想法*里的一个 bug，而那恰恰是整个重点。
- UI 变体在布局和信息层级上分歧，而不是只在颜色和文案上分歧，你得到的反馈是"B 的页头加上 C 的侧栏"。
- 它在一次坐下来就回答了。如果你第二天还在搭，问题就太大了；把它拆开。
- 结束时，main 包含决策、不含原型的任何一行，实现 issue 指向那条仍然保留着它的分支。

## 它的定位

`prototype` 是一个**随时可调用的独立技能**：你钻进它敲定一个设计问题，然后钻出来；它也是另一个技能运行的机器。

它最大的消费者是 [wayfinder](https://aihero.dev/skills-wayfinder)。一张 wayfinder 地图由**决策 tickets** 组成，而 `prototype` 是 ticket 可以是的那四种之一：当阻塞的问题是"这应该长什么样"或"这应该怎么行为"时用到的那种——再多讨论也敲不定的那种。Wayfinder 用做出某样具体东西让人反应来抬高一场模糊讨论的保真度，而这个技能就是那种具体东西如何被搭起来的途径。一张原型 ticket 由答案解决，原型作为一份资产被链接到地图上。

其他邻居是它的上游和下游。[grill-me](https://aihero.dev/skills-grill-me) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 回答可被盘问的问题；不可被盘问的那些走到这里来，一行答案再回到访谈里。下游，一个被验证的状态模型或 UI 方向变成 [to-spec](https://aihero.dev/skills-to-spec) 的敲定输入，它能内联原型产出的信息密集片段，而不是用散文描述它。任何别的情况，[ask-matt](https://aihero.dev/skills-ask-matt) 在整套技能之上给你路由。
