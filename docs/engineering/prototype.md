## 功能

`prototype` 构建一个小型、可丢弃的程序，其唯一职责就是回答一个设计问题——这个状态模型感觉对吗，或这个 UI 应该长什么样。

代码**从第一天起就是可丢弃的**，并被标记为如此。它不带任何测试，不带任何超出运行所需之外的错误处理，没有抽象，没有持久化。关键是快速学到东西——因此当你开始加固它时，你已经停止原型设计了。

## 何时使用

输入 `/prototype`，或者当任务合适时 Agent 会自动调用。

当你有一个在纸上难以确定的设计问题时使用——一个你无法在头脑中装下的状态机，或一个你不到看到几个版本并排就想象不出的界面。如果相反，已经构建好的东西行为不正确需要找出原因，使用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)；原型设计探索*要构建什么*，而不是*已构建的东西哪里坏了*。

## 两个分支

问题决定形状，有两种形状：

- **"这个逻辑/状态模型感觉对吗？"**——一个小的交互式终端应用，将状态机推过尴尬的情况，在每个动作后打印完整状态，以便你可以观察什么发生了变化。
- **"这应该长什么样？"**——同一条路由上几种截然不同的 UI 变体，可以从浮动栏切换，以便你比较真实的渲染效果而非凭空想象。

选错分支会浪费整个原型，因此先有问题是关键。两个分支都将状态保存在内存中，从一个命令运行，并在每一步显示完整状态。

## 将原型保留为第一手来源

一个完成后的原型会留下两样东西。**答案**——结论加上它所解决的问题——是你需要持久捕获的内容（一条 commit 消息、一个 ADR、一个 issue）。而**原型本身是一手来源**——答案背后的可运行证据。

原型不属于主分支：没有测试、没有错误处理、没有任何需要维护的东西。但这不代表要销毁它。一旦答案被捕获，将任何已验证的决策纳入真实代码，然后将原型提交到一个可丢弃的分支上——远离 main，永不合并——并在实现 issue 上留下一个指向它的上下文指针。Main 分支保持干净；原始的探索记录只需一次点击便可重新运行。一个在主分支上腐烂的原型已经超越了其存在的目的——而作为一个保留在侧分支的一手来源的原型则不然。

## 在生态中的位置

`prototype` 是一个随时可用的独立技能：你切入它来解析一个设计问题，然后退出。它的答案通常输入下一步——一个已验证的状态模型或 UI 方向成为 [to-spec](https://aihero.dev/skills-to-spec) 的确定输入以供编写，或一个值得通过 [domain-modeling](https://aihero.dev/skills-domain-modeling) 记录的架构决策。当你不确定哪个技能或流程适合时，[ask-matt](https://aihero.dev/skills-ask-matt) 会引导你。
