## 它能做什么

`wizard` 生成一个交互式 bash 脚本，逐步引导人类完成一个手动流程——配置第三方服务、运行一次性迁移、将项目从状态 A 搬到状态 B。它打开每个 URL，告诉你要点击和复制什么，捕获返回的内容，并将其写入 `.env` 文件和 GitHub Actions secrets。

## 何时使用

你直接输入 `/wizard` 来调用它；智能体不会自动触发。

| 你的情况 | 使用 |
| --- | --- |
| 有一个手动流程需要别人来执行 | `wizard` |
| 有一个手动流程需要你自己执行，但你想以后再做 | `wizard`——脚本比记事本好 |
| 有一个手动流程，你希望文档化但不是自己写 | `wizard`——脚本就是文档 |

## 先决条件

- 一个**手动流程**。`wizard` 自动化的是人类步骤，而不是代码步骤。
- 一个**输出**。`wizard` 生成一个脚本，而不是一个文档。

## 输出

`wizard` 把一个交互式 bash 脚本放在 `.scratch/wizard/` 下，以流程名称命名。脚本会：

- 打开每个 URL
- 告诉你要点击和复制什么
- 捕获返回的内容
- 将其写入 `.env` 文件和 GitHub Actions secrets

## 常见问题

**它生成的脚本太长了。**
流程太长了。把它拆分成更小的步骤。

**它生成的脚本容易出错。**
手动流程本身容易出错。脚本只是如实反映。

**它生成的脚本没有文档化。**
脚本就是文档。它比任何散文文档都更精确。

**它生成的脚本无法测试。**
脚本就是测试。它验证了手动流程是可行的。

## 如何判断它是否有效

- 脚本逐步引导完成手动流程。
- 脚本捕获返回的内容。
- 脚本将其写入 `.env` 文件和 GitHub Actions secrets。
- 脚本是可执行的，而不是可读的。

## 它适合在哪里

`wizard` 是一个**独立技能**，脱离所有流程。它适合在有一个手动流程需要别人来执行时使用。

- [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 是它用于你需要在执行之前思考的流程的对应物。
- [to-spec](https://aihero.dev/skills-to-spec) 是它用于你需要在执行之前规范化的流程的对应物。

[ask-matt](https://aihero.dev/skills-ask-matt) 在不清楚该用哪个技能时为你路由。
