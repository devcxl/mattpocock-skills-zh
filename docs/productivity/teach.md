## 它的作用

`teach` 把你运行它的目录变成一个常设的教学工作区，并在多次 [sessions](https://www.aihero.dev/ai-coding-dictionary/session) 中、用简短的自包含 HTML 课程教你一个主题。

它不靠 [model](https://www.aihero.dev/ai-coding-dictionary/model) 已经知道的东西来教。[Parametric knowledge](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge) 被视为不可信：在教之前，它会去找高可信度的资源，把它们记在 `RESOURCES.md`，并在每一课里引用它们。另一个结构性事实是它是 [stateful](https://www.aihero.dev/ai-coding-dictionary/stateful) 的：任务、资源、课程和你学过什么的记录都作为文件存放在该目录里，所以下一次 session 从那些文件接着来，而不是从上一段对话残留的东西。

## 何时使用

你通过键入 `/teach` 来调用它：[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不会主动触发它。

当学习本身就是那个项目时，就用它：一种语言、一个框架、你刚加入的代码库、瑜伽、着色器、一份认证。它不是用来顺带做一次解释的工具。

| 你想要什么 | 该用 |
| --- | --- |
| 用几周时间学习一个主题，让会话累积起来 | `teach` |
| 在你已有的 session 里解释一个想法 | 直接在那个 session 里问 |
| 因为智能体上一条消息没讲清楚而重新讲一遍 | [wait-what](https://aihero.dev/skills-wait-what) |
| 打磨你已经有的想法，而不是获取新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 让后台 agent 读 [primary sources](https://www.aihero.dev/ai-coding-dictionary/primary-source) 并留下一份带引用的文档 | [research](https://aihero.dev/skills-research) |
| 想学 grilling 中途冒出来的东西，又不想打断 [grilling](https://www.aihero.dev/ai-coding-dictionary/grilling) | [handoff](https://aihero.dev/skills-handoff) 出去到一个教学工作区，再在那里用 `teach` |

## 先决条件

`teach` 构建一个目录而不是产出一个文件，并且该技能假定一个 workspace 对应一个任务：所以在你愿意把整个目录交托给一个主题的地方运行它。把它放在你正在做的项目之外：一个独立的仓库是推荐的归宿，而不是全局的 `~/.learnings/` 目录，也不是那个工作项目本身。专用的仓库也使课程可以提交，团队正是这样共享它们的。

这个目录里会累积这些东西：

| 路径 | 它装着什么 |
| --- | --- |
| `MISSION.md` | 你为什么在学这个主题。其他一切挂在它之上；如果它缺失，`teach` 做的第一件事就是访谈你，直到它不缺失为止 |
| `RESOURCES.md` | 它拿来教的、经审核过的来源，拆分为"知识"和"智慧"（社区） |
| `lessons/*.html` | 编号的课程：教学的主要单元 |
| `reference/*.html` | 压缩的速查表、算法、词汇表：你真正会回访的文档 |
| `learning-records/*.md` | 风格类似 ADR 的笔记，记录你确实学到了什么，用来决定下一步教什么 |
| `assets/*` | 可复用的组件：首先是一份共享的样式表：让课程看起来像一门课 |
| `NOTES.md` | 你陈述的教学偏好 |

对这个列表的两个诚实说明。词汇表适合大多数主题，但这个技能带了一份 `GLOSSARY-FORMAT.md`，而 `SKILL.md` 已经不再链到它，所以你得主动要才会有一份（[issue #559](https://github.com/mattpocock/skills/issues/559)）。并且 workspace 不总是创建在你以为的地方：在你要在上面构建一门长课之前，先看看下面第一个问题。

## 存储强度，而非流利度

要思考的那个词是**存储强度**：长期保持，与**流利度**相对：流利度是当下能回忆出来的东西，读的时候感觉已经掌握，一周后就忘了。`teach` 通过"合意难度"：检索练习、间隔、交叉：建立前者。知识先来，此时难度是敌人，因为它会吃掉你理解时需要的工作记忆；然后该技能通过一个紧凑的反馈循环来打磨，此时难度就是工具。

两件事决定你被教什么。**任务**：你想要这个的真实世界理由：把每一课落地；没有它，课程会越飘越抽象，没有任何东西决定下一步。从任务和学习记录出发，`teach` 在你的**最近发展区**里挑下一课：难到需要努力，但又不至于远到不可学。

这也是为什么这个技能会反驳而不是迎合。一个需要**智慧**的问题：现实世界的判断：会得到一个尝试的回答，然后是指向一个你能去测试它的社区的指针。测验是一道关卡，不是走过场：一位用户报告说在说了句"thanks a lot"之后被告知练习仍在进行。

## 课程、参考文档与组件

一**课**是一个自包含的 HTML 文件，短到一次能坐下来读完，与任务挂钩，给出一个能落实的胜场。它引用自己的来源，推荐一个值得你自己去读的原始来源，并链接到兄弟课程和参考文档。

值得知道的拆分：课程很少被回访，参考文档会。所以一节课的压缩精华：语法表、算法、姿势序列、词汇表：属于 `reference/`，而不是埋在那节介绍它的课程里。

课程由 `assets/` 里的**组件**搭建：样式表、测验部件、模拟器、图表助手。复用是默认。Agent 在写一节新课之前先读 `assets/`，并从里面已有的东西搭起；任何第二课可能用得上的新东西，作为组件而不是内联来写。共享的样式表是每个 workspace 挣来的第一个组件；它让输出不再是一堆彼此无关的东西。

## 常见问题

**它把文件放哪？我的最后落在了 `~/.claude/skills`。**
一个真实的、尚未解决的 bug（[#377](https://github.com/mattpocock/skills/issues/377)）。`SKILL.md` 对 `./` 同时用了两种根：`./MISSION-FORMAT.md` 之类确实和 `SKILL.md` 并列放在已安装的技能里，而 `./lessons/`、`./reference/`、`./learning-records/` 和 `./assets/` 本意是在你的目录里。一个把第一种解析到技能安装目录的 agent，会继续把第二种也解析到那里，于是把你的课程写进了技能文件夹。在你往上堆东西之前先检查第一节课落到了哪里，并且显式给出目录名，而不是依赖"当前目录"被理解。

**我应该留在一个 session 里，还是每节课开一个新的？**
三种做法都行：留在同一个 session、在新 session 里重新调用 `/teach`、或在同一文件夹里开一个新的 session。每节课都是各自的一次调用。承接的是文件夹，不是对话。常见的做法是在 workspace 里开一个新的 session 然后说 `/teach next lesson for <topic>`。

**我怎么知道它没在教我编出来的东西？**
不能单凭技能的话来判断。你得读原始来源。`teach` 还不够可靠到让人不经核实地信任它，基于 LLM 的任何技能都不是。接地气的机制：`RESOURCES.md`、每节课里的引用、每节课一个推荐的原始来源：的存在是为了让验证变便宜，而不是为了消除验证的需要。失败不是假设的：一位在学 2×2 魔方的用户被给了根本无法解开的伪造步骤序列。对这种案例的诊断清单是模型、harness、投入度：以及来源是什么。风险最高的是带有精确符号的过程性领域，最低的是输出可以立刻验证的地方，比如你可以运行的代码。

**正确答案永远是第一个选项。**
几位用户在 Sonnet、Opus 和 GLM 上都确认了，仍未修复。`SKILL.md` 现在要求每个答案的字数相同，这消除了一种不同的迹象：以前正确答案往往是唯一被充分论证的那个：但对位置没说什么。一位贡献者测试了一个针对位置的指令级修复，报告说正确答案仍然有 33/33 落在 A 位上（[#335](https://github.com/mattpocock/skills/issues/335)），这指向 `assets/` 中一个洗牌的测验组件才是真正的修复，而不是更好的措辞。在这个修复发布之前，把答案位置当作无意义的。你的 `assets/` 目录是你可以改的，所以要求一个在渲染时洗牌的组件，是一个合法的本地修复。

**它假设我已经知道一些事，并用从未定义过的术语。**
最常见的实质性投诉。没有评估步骤：`teach` 从任务和学习记录反推你的水平，而第一节课还没有学习记录。一位在 wayfinder 流水线里跑它的用户说得直白："它从不做 grilling 来建立我的起点，所以它对'我已经知道什么'做了大量假设。"另一位报告说课程依赖未定义的术语，还有一节课是为他们的硬件量身定制，覆盖了硬件能做什么，却从没说过它不能做什么。两件事有帮助：在第一条消息里说清楚你已有的知识和盲区；在课程没中靶时口头纠正水平，因为纠正会成为学习记录，并引导下一课。一个显式的知识评估步骤是一个长期存在的功能请求（[#725](https://github.com/mattpocock/skills/issues/725)），不是已发布的行为。

**它做间隔重复吗？它知道什么时候该停止教吗？**
前一个不做，后一个不可靠。间隔和交叉是课程为之设计的原则，但没有任何东西排定复习，没有 Anki 或日历集成：两者都是反复的请求。相关的缺口是退出标准：正如一位用户所说，`teach` "擅长做下一节课，但不擅长知道何时停下来转入复习或真正的练习"。如果你想要复习或练习而不是新材料，主动提出；技能不会主动提议这种切换。

**它只对代码有用吗？**
不，非代码的用例是记录中更大的一部分：韩语、日语正式语域、钢琴、吉他、桌游设计、OpenSCAD、电影剧情、Azure 和 CCNA 认证、大学考试，还有八岁、十岁的孩子们打印出来的关于密室逃脱和火蝾螈的书。技能里没有任何东西是编程专属的：任务、资源、最近发展区和练习在任何领域都一样好用。在代码范围内，被报告最多的强用例不是从零学一门语言，而是在一个陌生的代码库或新团队的栈里定向。

**我应该用什么模型跑它？**
没有标准答案，被报告出来的差异很大。较高的 [reasoning effort](https://www.aihero.dev/ai-coding-dictionary/effort) 已被报告说产出的课程明显好于中等设置。一位用户用 Copilot CLI 加 Codex 跑同一个技能，得到了一张 30 行的 HTML 卡片，而 Claude Code 产出的是一节完整的课程。它在 Claude Cowork 里无需修改即可运行，前提是你的组织允许在那里添加技能。如果课程出来很薄，换模型、换 [harness](https://www.aihero.dev/ai-coding-dictionary/harness) 或换投入度，再去改你的提示词。

## 怎样算成功

- 它在空目录里做的第一件事，是就"你为什么想要这个"对你访谈，而不是产出一节课。
- `RESOURCES.md` 先填满，课程随后；每节课指明一个值得你自己读的原始来源。
- 课程里的断言都带外链。一节没有引用的课程，是技能在凭记忆教。
- 一节课一次能坐下来读完，让你能在结束时会做一件之前不会的事。
- 在该文件夹里新开一个 session 说"next lesson"，课程继续而不是重启。
- `learning-records/` 在增长，课程不再重复你已经证明学会的东西。
- 课程看起来像一门课：它们链接 `assets/` 中的样式表，而不是每节自带一份。
- 一个需要判断的问题让你被指向一个论坛、subreddit 或班级，而不只是给一个答案。

## 它的定位

`teach` 是一个**可随时取用的独立工具**。它不是构建链里的一步，也不与工程流共享工件；它拥有自己的目录，住在那里，直到那个主题走完。

它真正唯一的邻居是 [handoff](https://aihero.dev/skills-handoff)，通过 Matt 给出的对"我在被 grilling 问我不懂的东西时该怎么办"的回答串联起来：别停下 grilling 去学：`/handoff` 到一个教学工作区，在那里用 `/teach` 学它，然后回去接着被问的地方。附近的替代是 [research](https://aihero.dev/skills-research)，适用于你想要一份带引用的文档，而不是课程和保持度。当你不确定哪个技能或流程合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 在整个集合上为你路由。
