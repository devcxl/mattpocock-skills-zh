## 它的作用

`teach` 把你运行它的目录变成一个常设的教学工作区，并跨许多[会话（session）](https://www.aihero.dev/ai-coding-dictionary/session)教你一个主题，以简短的自包含 HTML 课程为单元。

它不是从[模型（model）](https://www.aihero.dev/ai-coding-dictionary/model)已经知道的教。[参数知识（parametric knowledge）](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)被当作不可信：在教之前，它去找到高信任的资源，记录在 `RESOURCES.md` 里，并在每节课内部引用它们。另一个结构性事实是它是[有状态（stateful）](https://www.aihero.dev/ai-coding-dictionary/stateful)的——使命、资源、课程和你已学内容的记录都作为文件活在目录里，所以下一个会话从那些文件继续，而不是从上一次对话剩下的任何东西继续。

## 何时使用

你通过键入 `/teach` 来调用它——[代理（agent）](https://www.aihero.dev/ai-coding-dictionary/agent)不会主动使用它。

当学习本身就是项目时使用它：一门语言、一个框架、一个你刚加入的代码库、瑜伽、着色器、一个认证。它不是顺带解释一个问题一次的工具。

| 你想要什么 | 使用什么 |
| --- | --- |
| 用几周学一个主题，会话不断积累 | `teach` |
| 在你已经所在的会话里解释一个想法 | 就在那个会话里问 |
| 代理的上一条消息因为没讲明白而重新推销 | [wait-what](https://aihero.dev/skills-wait-what) |
| 磨锐你已经拥有的思考，而不是获取新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 一个后台代理读[一手来源（primary sources）](https://www.aihero.dev/ai-coding-dictionary/primary-source)并留给你一份带引用的文档 | [research](https://aihero.dev/skills-research) |
| 学一个盘问中途冒出来的东西，又不让[盘问（grilling）](https://www.aihero.dev/ai-coding-dictionary/grilling)脱轨 | [handoff](https://aihero.dev/skills-handoff) 到教学工作区，然后在那里 `teach` |

## 前置条件

`teach` 构建一个目录而不是产出一个文件，而且技能假定每个工作区一个使命——所以把它运行在你乐意交给单一主题的地方。让它远离你正在做的项目：推荐的家是一个独立仓库，而不是一个全局 `~/.learnings/` 文件夹或工作项目本身。一个专用仓库也让课程可提交，这正是团队分享它们的方式。

那个目录里积累的东西：

| 路径 | 它容纳什么 |
| --- | --- |
| `MISSION.md` | 你为什么学这个。其他一切都挂在它下面；如果它缺失，`teach` 做的第一件事就是访谈你直到它不再缺失 |
| `RESOURCES.md` | 它据以教学的经过审查的来源，分为知识（Knowledge）和智慧（Wisdom，社区） |
| `lessons/*.html` | 编号的课程——教学的主要单元 |
| `reference/*.html` | 压缩的速查表、算法、词汇表：你真正回来查阅的文档 |
| `learning-records/*.md` | 关于你已切实学到什么的 ADR 式笔记，用来决定接下来教什么 |
| `assets/*` | 可复用组件——先是一个共享样式表——让课程看起来像一门课 |
| `NOTES.md` | 你陈述的教学偏好 |

对那张清单有两条诚实的说明。词汇表适合大多数主题，但技能随附的 `GLOSSARY-FORMAT.md` 已经不被 `SKILL.md` 链接了，所以你只有开口要才会得到一个（[issue #559](https://github.com/mattpocock/skills/issues/559)）。而且工作区并不总是在你预期的地方创建——在它上面建一门长课之前，先看下面的第一个问题。

## 存储强度，不是流畅性

用来思考的词是**存储强度（storage strength）**：长期保留，相对于**流畅性（fluency）**——那种阅读当下感觉像掌握、一周后就没了的一时回忆。`teach` 通过合意困难（desirable difficulty）——提取练习、间隔、交错——构建前者。知识先来，此时困难是敌人，因为它吃掉你理解所需的 working memory；然后技能通过紧反馈回路被操练，此时困难是工具。

两样东西引导你被教什么。**使命（mission）**——你想要这个的具体现实理由——为每节课奠基；没有它，课程会漂向抽象，没有什么决定接下来是什么。从使命和学习记录出发，`teach` 在你的**最近发展区（zone of proximal development）**内挑下一课：有挑战到需要努力，又不至于远到不再可学。

这也是技能顶回去而不是顺从的原因。一个需要**智慧（wisdom）**——现实世界的判断——的问题会得到一个尝试性的回答，然后一个你可以去验证它的社区指针。一次测验是闸门，不是走过场：一位用户报告说了"非常感谢"，却被告知操练还活着。

## 课程、参考和组件

一节**课程（lesson）**是一个自包含的 HTML 文件，短到一口气能读完，与使命挂钩，给一个实实在在的胜利。它引用来源，推荐一份值得你自己去读的一手来源，并链接到兄弟课程和参考文档。

值得知道的划分：课程很少被重访，参考文档经常。所以一节课的压缩精华——语法表、算法、体式序列、词汇表——属于 `reference/`，而不是埋在引入它的课程里。

课程由 `assets/` 里的**组件（components）**构建：样式表、测验小部件、模拟器、图表助手。复用是默认。代理在写课前读 `assets/`，从已有的东西构建，而任何第二节课可能用到的新东西都被写成组件而不是内联。共享样式表是每个工作区挣到的第一个组件；它是让输出不是一堆一次性作品的东西。

## 常见问题

**它把文件放哪了？我的最后进了 `~/.claude/skills`。**
一个真实的未决 bug（[#377](https://github.com/mattpocock/skills/issues/377)）。`SKILL.md` 同时用 `./` 指两个不同的根：`./MISSION-FORMAT.md` 和它的兄弟们确实坐在已安装技能里 `SKILL.md` 旁边，而 `./lessons/`、`./reference/`、`./learning-records/` 和 `./assets/` 本应在你自己的目录里。一个按技能安装目录解析第一种的代理，会继续在那里解析第二种，把你的课程写进技能文件夹。在它上面继续构建之前，检查第一节课落在哪里，并在开始时显式命名目录，而不是指望"当前目录"被理解。

**我留在同一个会话里，还是每节课开新的？**
三种做法都行——留在同一个会话、在新会话里重新调用 `/teach`、或在同一个文件夹里开新会话。每节课是它自己的一次调用。文件夹是连续性，不是对话。常见做法是在工作区开一个新会话，说 `/teach next lesson for <topic>`。

**我怎么知道它不是教我它编造的东西？**
单凭技能的话，你不知道。你读一手来源。`teach` 还不足以被不检查地信任，任何建立在 LLM 上的技能都不够。接地机制——`RESOURCES.md`、每节课的引用、每节课一份推荐的一手来源——存在是为了让验证变便宜，不是消除验证的需要。失败不是假设性的：一位学 2x2 魔方的用户被给了解决不了的编造转动序列。那种案例的诊断清单是模型、harness、投入度——以及来源是什么。风险在具有精确记号的程序性领域最高，在输出立即可验证的地方最低，比如你能运行的代码。

**正确的测验答案总是第一个选项。**
好几个人确认过，在 Sonnet、Opus 和 GLM 上，而且仍未修复。`SKILL.md` 现在要求每个答案字数相同，这杀掉了另一个特征——正确答案曾经是唯一推理完整的那个——但对位置什么都没说。一位贡献者测试了一个指示层面的位置修复，报告正确答案在九节课里 33 次全部仍落在 A 槽（[#335](https://github.com/mattpocock/skills/issues/335)），这指向 `assets/` 里一个打乱顺序的测验组件才是真正的修复，而不是更好的措辞。在那发布之前，把答案位置当作无意义。你的 `assets/` 目录归你改，所以要一个渲染时打乱的组件是合法的本地修复。

**它假定我已经知道一些东西，用了它从未定义的术语。**
最常见的实质性抱怨。没有评估步骤：`teach` 从使命和学习记录推断你的水平，而在第一个会话里没有学习记录。一位用户在 wayfinder 流水线里跑它，说得直白——"它从来没做盘问来确立我的起点，所以它对我已经知道什么做了大量假设。"另一位报告课程依赖未定义的术语，还有一节课针对他们的硬件定制，讲了硬件能做什么、却从没说它不能做什么。两件事有帮助：在第一条消息里陈述你的先验知识和缺口；当一节课打偏时大声纠正水平，因为纠正会变成学习记录、引导下一节。一个显式的知识评估步骤是一个常设功能请求（[#725](https://github.com/mattpocock/skills/issues/725)），不是已发布的行为。

**它做间隔重复吗？它知道什么时候该停止教吗？**
第一个没有，第二个不可靠。间隔和交错是课程按其设计的原理，但没有任何东西安排复习，也没有 Anki 或日历集成——两者都是反复出现的请求。相关的缺口是退出标准：正如一位用户所说，`teach`"擅长做下一节课，但不擅长知道什么时候该停下、转向复习或真实练习。"如果你想要复习或操练而不是新材料，开口要；技能不会自己提议切换。

**它只对代码有用吗？**
不，非代码用途是记录里更大的部分：韩语、日语敬语、钢琴、吉他、桌游设计、OpenSCAD、电影情节、Azure 和 CCNA 认证、大学考试，以及八岁和十岁的孩子拿到关于密室逃脱和火蝾螈的可打印书。技能里没有任何编程特定的东西——使命、资源、最近发展区和操练在任何领域都以同样的方式工作。在代码内部，被报告最强的用途不是从零学一门语言，而是在不熟悉的代码库或新团队的栈里找到方向。

**我该用哪个模型跑它？**
没有规范答案，而报告出来的差异很大。更高的[推理投入度（reasoning effort）](https://www.aihero.dev/ai-coding-dictionary/effort)被报告产出明显优于中等设置的课程。一位用户通过 Copilot CLI 带 Codex 跑同一个技能，得到一张 30 行的 HTML 卡片，而 Claude Code 产出了完整课程。它在 Claude Cowork 里不改动就能跑，取决于你的组织是否允许在那里添加技能。如果课程出来很薄，在重写你的提示词之前先换模型、[harness](https://www.aihero.dev/ai-coding-dictionary/harness) 或投入度。

## 怎样算成功

- 它在空目录里做的第一件事是访谈你为什么想要这个，而不是产出一节课。
- `RESOURCES.md` 在课程之前填满，每节课点名一份值得自己读的一手来源。
- 课程里的论断带着出去的链接。没有引用的课程就是技能在凭记忆教。
- 一节课花一口气读完，让你能做一件之前做不到的事。
- 在文件夹里开新会话、说"下一课"，会继续课程而不是重启它。
- `learning-records/` 增长，课程停止重教你已展示过的内容。
- 课程看起来像一门课——它们链接 `assets/` 里的样式表，而不是各自带一份。
- 一个需要判断的问题让你被指向论坛、subreddit 或课堂，而不只是一个答案。

## 它的定位

`teach` 是一个**随时可取的独立技能**。它不是构建链里的一步，与工程流程不共享任何工件；它拥有自己的目录，在主题存续期间住在那里。

它唯一真正的邻居是 [handoff](https://aihero.dev/skills-handoff)，通过 Matt 命名为"被盘问到我听不懂的东西时我该怎么办"答案的组合：不要停下来学习——`/handoff` 到一个教学工作区，在那里用 `/teach` 学，然后回去接上你停下的地方。近旁的替代是 [research](https://aihero.dev/skills-research)，用于你想要的是带引用的文档而不是课程和保留时。拿不准哪个技能或流程合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 会带你路由整个集合。
