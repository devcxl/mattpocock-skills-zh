# 阶段边界

**阶段**是一次会话中的一块工作：盘问（grilling）、实现、QA。这个定义刻意保持模糊：一个阶段结束的时候，你会想"好了，那块搞定了"。

**阶段边界**是两个阶段之间的缝隙，也是这一决策唯一应该出现的地方。阶段中间没有决策要做：要么继续，要么把剩下的工作拆给 subagent。阶段中间做压缩会让 agent 丢掉主线。

## 五个选项

| 选项 | 它做了什么 |
| --- | --- |
| **Continue** | 留在当前会话，完全不切换上下文。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写一个可移植的 markdown 文件，并用它在任意地方开启一个会话。 |
| **Subagent** | 把任务送进自己的上下文窗口，拿回一份报告。 |
| **`/compact`** | 压缩当前上下文，并用这份摘要开启一个新的会话。 |

## 决策树

在边界处从上到下走。第一个 **是** 胜出。

**1. 你能在当前会话继续吗？** 两种情况答案是"是"：下一阶段把这一阶段作为**主要来源**（primary source）来用，或者你还有足够 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k tokens）留给下一阶段。盘问 → 实现是标准的"是"：实现要的是逐字逐句的推理，而不是它的摘要。继续不花钱也不损失任何东西，所以先把它排除掉。

**2. 这个上下文和接下来的内容无关吗？** 这个会话里的所有东西（探索、决策、死胡同）都是可以丢弃的吗？如果是，就 **`/clear`**。这是棋盘上最便宜的一步：它不花时间，并且把整块窗口都还给你。`/clear` 也不是终态：旧会话仍然可以恢复。

搞错的代价是不可逆的。清掉一份**相关的**上下文，你就把构建背后的**为什么**丢了，再怎么回去读 diff 也找不回来。

**3. 你需要交接吗？** `/handoff` 的适用范围很窄。你只在以下情况才需要它：

- 切换到**新的 harness**（Claude → Codex），
- 转到**新目录**或仓库，
- 把工作交给**同事**，
- 或者在阶段中**分叉出一个**侧任务而不想打断当前工作。

那个清单就是这条规则的全部。`/handoff` 买到的是**可移植性**：一个会"移动"的文件。如果没有东西要移动，你就不需要它。

**4. 任务能 AFK 完成吗？** 它的范围是否足够紧凑，让你离开键盘、不用中途介入就能跑完？如果是，就派给一个 **subagent**，保持当前会话不动。自动审查就是典型场景：agent 读 diff、写报告，你不在场也没问题。

**5. 否则，`/compact`。** 上下文相关、同一个 harness、同一个目录，而且你需要保持在循环里：决策树走到这里，而且经常走到这里。给它传一条指令（`/compact 我们要去 QA 这个区域`），让摘要保住下一阶段需要的内容。

`/compact` 是**默认选项，但不是首选**。它位于底部，是因为它上面的四个问题每一个都更便宜或更精确。当人们从这里起步时，常见的失败模式是一个新会话对被摘要压平的决策充满自信地给出错误答案。

## 主要来源和次要来源

除了 **Continue**，每一次移动都把**主要来源**变成**次要来源**：原本按事件发生的会话，被它的摘要所取代。这种权衡的形式总是一样的：

| 来源 | 信息量 | 噪声 | 发挥空间 |
| --- | --- | --- | --- |
| 主要（Continue） | 完整 | 多 | 小 |
| 次要（`/compact`、`/handoff`） | 有损 | 少 | 多 |

这就是为什么问题 1 要先问。只有当"留下来"的代价大于它节省的东西时，你才付出这种有损性。

## 这些都是判断题

这些问题不是客观的：每一个都掺杂着判断，同一条边界在不同的两天可能走向不同的方向。价值在于**按顺序**、在边界处而不是工作中间去问它们。
