# 诊断 Bug

对棘手的 bug 和性能回归问题进行诊断排查。使用一个纪律性的人类在环（HITL）循环，逐步缩小范围，定位根本原因。

## 脱敏

此技能会展示命令、输出和捕获的产物。**先脱敏所有秘密**——用 `<REDACTED>` 替换。对环境变量构建循环，这样凭证留在环境中而非你展示的内容中。捕获的产物携带认证头：只引用携带信号的行。

如果脱敏后的输出不足以诊断 bug，请说明并询问用户。

## 流程

### 1. 启动 HITL 循环

使用 [hitl-loop.template.sh](./scripts/hitl-loop.template.sh) 来构建一个逐步排查的问题列表。**不要自己编写 HITL 脚本**——使用模板。

### 2. 编写 HITL 脚本

阅读有问题的代码模块。使用模板中的 `ASK` 函数来提问，引导人类提供运行时信息（日志、错误、截图、观察到的行为）。

**不要问全是/否的问题**——问题是用来缩小范围的，而不是用来确认假设的。好的问题："在 `processData` 中，`response` 变量是什么？" 而不是 "是不是 `processData` 中的 `response` 出了问题？"

模板自带提示。跑一下 `bash -n` 检查语法，然后交给用户运行。

### 3. 排查

让用户运行脚本。他们会一步步回答，你逐步缩小范围。一旦你确定根本原因，进入下一步。如果脚本需要修正，用 `bash` 重写并让用户重新运行。

### 4. 修复

- 实施修复。
- 添加测试，覆盖失败场景。
- 在 issue 中回复，说明发现和修复方案。

## 何时使用 HITL 循环

- 测试难以覆盖的 bug（竞态条件、特定环境、UI 交互）
- 性能回归问题
- 任何需要运行时信息才能定位的问题

## 何时不使用 HITL 循环

- 你可以通过阅读代码直接找到 bug
- 你可以在不人工干预的情况下重现问题
- 你只需要运行测试或代码检查来验证
