# 技能机制

[`writing-for-agents`](SKILL.md) 中专门针对技能（skill）的分支：当文档是一个技能时会发生变化的内容：前置元数据（frontmatter）、调用方式的选择，以及路由技能（router skill）。除此之外的所有写作规则，均适用 `SKILL.md` 中的通用参考。

## 调用方式

两种选择，在两种"负载"之间权衡：

- **模型调用（model-invoked）** 的技能保留 `description`，因此智能体可以自主触发它，其他技能也可以触达它。你依然可以手动输入它的名字：模型调用始终*包含*用户触达的能力；`description` 只是为智能体增加发现性，永远不会削弱人类的可达性。这个 `description` 是技能最高层的上下文指针，强制始终驻留在上下文中：用永久的上下文负载，换来可发现性。一个内容全是参考资料的模型调用技能，也是共享参考的一个归宿：另一个技能可以调用它，所以几个技能都需要的那部分参考资料集中放在一处即可。实现要点：省略 `disable-model-invocation`，并写一段面向模型的 `description`，承载触发分支（`SKILL.md` 中关于指针写作的所有规则全部适用）。
- **用户调用（user-invoked）** 的技能把 `description` 从智能体的触达范围中剥离：只有人类手动输入它的名字才能触发，其他技能也无法触达。零上下文负载，但它消耗认知负载：你成了那个必须记得它存在的索引。实现要点：设置 `disable-model-invocation: true`；此时 `description` 是面向人类的：一句摘要，不再保留触发词列表。

只有在智能体必须自己找到这个技能，或者另一个技能必须触达它时，才选择模型调用。如果它只会被手动触发，那就做成用户调用，免去任何上下文负载。

两个用户调用的技能都需要的那部分共享参考资料，无法放在它们两者任一处：因为没有 `description`，它们彼此都无法触发对方。把它放到技能系统之外的一个普通文件里：作为任何技能都可以指向的外部参考资料。

## 按调用方式拆分

"何时拆分"的"调用方式"这一刀（"顺序"那一刀在 `SKILL.md` 中）：当存在一个明确的"引导词"（leading word）应该独立触发它（一个你真的会在 prompt 里使用的触发词），或者另一个技能必须触达它时，就把一个技能拆出来作为模型调用的技能。你要为新的"始终加载的 description"付出上下文负载，所以这种独立的可达性必须值得才行。

## 路由技能

当用户调用的技能多到你记不住时，这种堆积起来的认知负载可以通过**路由技能**来解决：一个用户调用的技能，列出其他所有技能及其各自的适用场景，于是人类只需要记住这一个技能。它只能提示（hint），永远无法触发其他用户调用的技能：用户调用的技能没有 `description`，因此除了人类之外，没有任何东西能触达它们。
