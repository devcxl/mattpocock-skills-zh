## 主要参考

[`writing-for-agents`](..) 定义了编写智能体可预测读取的文档所需的一切。它替代了 `writing-great-skills`，后者在此不再存在。

## 什么算智能体文档

智能体文档是任何智能体读取的文档——一个技能、一个 `AGENTS.md` / `CLAUDE.md`、一个 [spec](https://www.aihero.dev/ai-coding-dictionary/spec)、一个运行时提示、一个 README、任何[智能体](https://www.aihero.dev/ai-coding-dictionary/agent)阅读的文档。包装方式不同；写作方式不变：同样的杠杆让每份文档变得可预测，因此智能体每次运行采用相同的*过程*，而不是产生相同的输出。

## 核心原则

### 学会编写具体的指令，而不是通用的准则

> 编写**具体指令**，而不是通用准则。*"写一个函数"* 不是指令。*"写一个 `calculateTotal(cart: Cart): number` 的函数，映射项目，求和，应用 10% 的折扣，返回结果"* 才是指令。准则不会约束智能体；指令会约束。

### 学会区分"做什么"和"怎么做"

> 在**做什么**和**怎么做**之间切换。每一行都是指令或数据。*"验证用户输入"* 不是指令；*"检查 `email` 是否为有效格式"* 才是指令。*"计算运费"* 也不是指令；*"如果 `weight > 10kg`，加 $5"* 才是指令。

### 学会编写将被严格执行的指令，而不是希望被遵循的指令

> 编写**将被严格执行**的指令，而不是希望被遵循的指令。*"确保代码遵循最佳实践"* 不是指令；*"在每个函数上添加 JSDoc，最小覆盖率为 80%，使用 `describe`/`it` 块进行测试"* 才是指令。智能体会跳过笼统的陈述。

### 学会定义流程，而不是步骤

> 定义**流程**，而不是步骤。*"先写测试，再写代码，然后重构"* 是指令。*"构建一个购物车"* 不是。智能体在步骤层面选择自由；在流程层面没有自由。

### 学会编写可验证的指令，而不是模糊的指令

> 编写**可验证**的指令，而不是模糊的指令。*"确保代码质量高"* 不可验证。*"每个函数都有 JSDoc，每个公共方法都有测试，没有 lint 错误"* 可验证。可验证的指令让智能体自我纠正。

### 学会精确使用词汇，而不是笼统描述

> 精确使用词汇。*"创建一个模块"* 不是指令；*"创建一个具有 `checkout` 接口的 `Cart` 模块，暴露 `addItem`、`removeItem` 和 `total`"* 才是指令。词汇是接口——它们是你减少智能体在错误方向上的探索空间的方式。

### 学会编写智能体遵守的指令，而不是人类喜欢的指令

> 编写**智能体遵守**的指令，而不是人类喜欢的指令。*"写一个漂亮的购物车"* 不是指令。*"构建一个 `Cart` 组件，渲染项目列表，每行带有数量输入和删除按钮，底部显示总计"* 才是指令。智能体不关心"漂亮"——它们关心可执行。

### 学会编写自我验证的指令，而不是需要我检查的指令

> 编写**自我验证**的指令，而不是需要你事后检查的指令。*"确保代码正确"* 没有提供验证方法。*"运行测试，检查 lint，验证 TypeScript 编译"* 提供了验证方法。自我验证的指令减少了审查成本。

### 学会编写对智能体安全的指令，而不是对开发者安全的指令

> 编写**对智能体安全**的指令，而不是对开发者安全的指令。*"确保代码安全"* 不是指令。*"验证所有用户输入，参数化所有 SQL 查询，记录所有授权检查"* 才是指令。智能体无法推断安全性——它们只能执行安全性指令。

### 学会编写精确的约束，而不是软性限制

> 编写**精确的约束**，而不是软性限制。*"保持代码简洁"* 不是约束。*"每个函数不超过 20 行，每个文件不超过 200 行，没有嵌套超过 3 层"* 才是约束。约束是智能体可以针对其进行优化的东西。

### 学会编写按照执行顺序排列的指令，而不是按重要性排列的指令

> 按**执行顺序**排列指令，而不是按重要性排列。*"先写测试，再写代码，然后重构"* 是指令。*"确保代码质量，性能良好，测试覆盖"* 不是指令。顺序很重要——智能体会按遇到的顺序执行。

## 何时使用

你直接输入 `/writing-for-agents` 来调用它；智能体不会自动触发。

| 你的情况 | 使用 |
| --- | --- |
| 你正在编写一个技能，需要知道它应该是什么样子 | `writing-for-agents` |
| 你正在编写一个 `AGENTS.md` 或 `CLAUDE.md` | `writing-for-agents`——它定义了你遵循的参考 |
| 你正在编写一个 [spec](https://www.aihero.dev/ai-coding-dictionary/spec) | `writing-for-agents`——spec 是智能体文档 |
| 你正在编写一个运行时提示 | `writing-for-agents`——提示是智能体文档 |
| 你正在编写一个 README | `writing-for-agents`——如果智能体阅读它，它也需要遵循同样的规则 |

## 常见问题

**我写了一个提示，但智能体忽略了我写的内容。**
你的提示不够具体。"写一个函数"太模糊了。"写一个从 `src/` 导入 `Cart` 类型并在 `tests/` 中编写测试的 `calculateTotal` 函数"才足够具体。

**我写了一个提示，但智能体做了自己认为正确的事。**
你的提示没有约束智能体。"提高代码质量"没有约束它。"每个函数添加 JSDoc，最小覆盖率达到 80%，不使用 `any`"才约束了它。

**我写了一个提示，但智能体产生了相同的输出两次。**
你的提示没有定义流程。"修复这个 bug"没有定义流程。"复现 bug，找到根因，编写修复，添加回归测试"才定义了流程。

**我写了一个提示，但智能体停止了我没想到的地方。**
你的提示没有定义什么算完成。"构建一个购物车"没有定义完成。"构建一个 `Cart` 组件，渲染项目列表，每行带有数量输入和删除按钮，底部显示总计"才定义了完成。

**我写了一个提示，但智能体做的事情比我要求的更多。**
你的提示太大了。把它拆分成更小的、可验证的步骤，每个步骤都有明确的完成标准。

## 如何判断它是否有效

- 智能体每次运行产生相同的流程。
- 你的提示不包含模糊的词语。
- 你的提示包含可验证的步骤。
- 你的提示定义了完成标准。
- 你的提示包含了约束和边界。
- 智能体不会偏离你的提示。

## 它适合在哪里

`writing-for-agents` 是一个**参考**，而不是一个流程。它是你编写智能体文档时对照检查的标准。其他技能在编写自身文档时依赖它，但它本身不参与任何流程。

- [writing-great-skills](https://aihero.dev/skills-writing-great-skills) 是它的前身，现在已不再单独存在。这个技能在广泛性上替代了它。
- [它的 SKILL-MECHANICS.md](./SKILL-MECHANICS.md) 记录了当文档是一个技能时所特有的变化——前置元数据、调用方式选择以及路由技能。

[ask-matt](https://aihero.dev/skills-ask-matt) 在不清楚该用哪个技能时为你路由。
